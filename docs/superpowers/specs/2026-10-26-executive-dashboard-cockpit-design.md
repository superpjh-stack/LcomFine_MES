# 엘컴화인 MES 전사 경영 Cockpit 설계

작성일: 2026-10-26  
상태: 사용자 승인 설계 1~4를 통합한 구현 기준  
대상: RPT-010~080, 경영목표, 위험·조치관리, 단계적 ERP 재무연계

## 1. 목적과 성공 기준

대표·임원·부서장이 수주부터 수금까지의 경영 흐름을 짧은 시간 안에 파악하고, 이상 징후의 원인과 담당 조치까지 내려갈 수 있는 전사 경영 Cockpit을 만든다.

성공한 화면은 단순 실적 모음이 아니라 다음 질문에 답한다.

- 일간: 오늘 무엇이 막혔고 즉시 조치할 것은 무엇인가?
- 주간: 목표에서 어디가 벗어났고 어느 부서·공정이 원인인가?
- 월간: 수주가 생산·출하·수금·이익으로 어떻게 전환되고 있는가?

완료 기준은 다음과 같다.

1. 수주, 생산, 품질, 재고·창고, 출하, 수금, 주문흐름, 경영요약의 8개 대시보드가 같은 경영 언어로 연결된다.
2. 각 KPI가 실적, 목표, 달성률, 전기 대비, 상태를 일관되게 제공한다.
3. 일간·주간·월간 모드가 서로 다른 경영 질문과 비교 기간을 사용한다.
4. 위험 항목에서 근거 수치, 담당 조치, 원천 업무 화면까지 추적할 수 있다.
5. 데이터 없음, 실제 0, 기준 미확정, 외부 연계 전 상태를 구분한다.
6. 모든 그래프 수치는 같은 화면의 접근 가능한 데이터 표 및 독립 재계산과 일치한다.
7. 기존 MES 업무흐름, 권한, 감사로그 및 RPT 회귀 테스트를 깨뜨리지 않는다.

## 2. 범위

### 2.1 이번 구현 범위

- RPT-080을 중심으로 한 전사 경영 Cockpit
- RPT-010~070 전문 대시보드 강화
- 일간·주간·월간 관점과 전기 비교
- 연간·월간·주간 경영목표 입력, 배분, 버전 이력
- 지표별 주의·위험 임계치
- 규칙 기반 위험 감지와 담당 부서·담당자·기한·상태 관리
- 목표·위험·조치 변경 감사로그
- ERP 재무자료 업로드 회차와 거래처·품목·기간별 금액·원가 데이터
- 수주금액, 출하매출, 재고금액, 원가, 매출총이익의 단계적 활성화
- 기존 인라인 SVG 차트 및 동일 수치 표의 확장

### 2.2 후속 범위

- 생성형 AI 원인 분석과 권장 조치
- 통계·ML 기반 예측 달성률
- 설비 실시간 수집
- 고객 클레임 시스템 자동 연계
- 외부 ERP API 실시간 연계

초기 구현은 규칙 기반 설명과 근거 링크까지만 제공한다. AI는 현재 D-529로 제거된 데이터 질의를 우회하여 재도입하지 않는다.

## 3. 설계 원칙

### 3.1 결과에서 조치까지

모든 대시보드는 `결과 → 추세 → 원인 → 위험 → 조치` 순서로 읽힌다. 경영요약에서 이상을 발견하고 전문 화면에서 원인을 좁힌 뒤 원천 업무 화면에서 조치한다.

### 3.2 원천 데이터 우선

- 현재 MES 원천 데이터는 화면을 열 때 다시 집계한다.
- 목표, 임계치, 위험, 조치만 관리 테이블에 저장한다.
- 집계 결과를 별도 캐시 테이블에 적재하지 않는다.
- 재무 데이터는 원천 파일 회차를 보존하고 활성 회차만 집계한다.

### 3.3 모르는 값을 지어내지 않음

- 행이 없거나 수집되지 않음: `미수집`
- 측정 결과가 실제로 영: `0`
- 공식 산식이나 기준이 없음: 기존 결정 번호가 있으면 `미확정 (D-519)`·`미확정 (D-520)`, 없으면 `기준 미확정`
- ERP 필드가 아직 연결되지 않음: `연계 전`
- 잘못된 업로드 행: 집계 제외 후 오류 사유 제공

### 3.4 조회와 관리 권한 분리

기존 RPT-010~080은 읽기 전용 계약을 유지한다. 목표·임계치·위험·조치·재무 업로드는 별도 관리 화면과 쓰기 기능으로 분리한다. RPT 조회 권한만 가진 사용자가 관리 데이터를 수정할 수 없어야 한다.

## 4. 정보 구조와 공통 화면

### 4.1 전사 경영 Cockpit

RPT-080은 다음 다섯 층으로 구성한다.

1. 기간, 모드, 거래처 등 공통 필터
2. 핵심 경영 KPI
3. 수주부터 수금까지의 흐름
4. 경영 위험 Top 5와 조치 상태
5. 영역별 요약 및 전문 대시보드 링크

상단 KPI 후보는 다음과 같다.

- 수주금액·수주수량
- 생산계획 달성률
- 품질 합격률
- 재고금액·장기재고
- 출하금액·납기 준수율
- 수금액·미수금
- 매출총이익률
- 현금전환주기

재무 연계 전에는 금액·원가 기반 KPI를 `연계 전`으로 표시하고 수량 기반 KPI를 우선 제공한다.

### 4.2 전사 흐름

`수주 → 생산대기 → 생산 → 검사 → 제품재고 → 출하 → 수금` 단계마다 건수, 수량, 평균 체류시간을 표시한다. 재무 활성 회차가 있으면 금액도 표시하고, 없으면 금액 칸만 `연계 전`으로 둔다. 단계 클릭 시 관련 전문 대시보드에 동일 기간·거래처 필터를 넘긴다.

### 4.3 공통 화면 골격

전문 대시보드는 다음 구조를 공유한다.

1. 기간·거래처·품목·창고 필터
2. 핵심 KPI와 목표 비교
3. 기간 추세 및 구성 그래프
4. 위험·병목·예외 목록
5. 근거 데이터 표와 업무 화면 드릴다운

데스크톱에서는 높은 정보 밀도를 유지하고, 390px 화면에서는 카드와 차트를 한 열로 쌓는다. 페이지 전체 가로 스크롤은 허용하지 않으며 넓은 표만 기존 `grid-wrap` 내부에서 스크롤한다.

## 5. 시간 관점과 비교 규칙

| 모드 | 기본 범위 | 비교 기준 | 강조 내용 |
|---|---|---|---|
| 일간 | 기준일 하루 | 전일 | 긴급 이상, 납기 임박, 설비 정지, 품질 보류, 당일 출하·수금 |
| 주간 | 기준일까지 7일 | 직전 7일 | 목표 달성, 공정 병목, 거래처·품목 편차, 조치 진행 |
| 월간 | 월 1일~기준일 | 전월 동기간 | 매출·원가·이익, 재고회전, 미수, 현금 흐름, 장기 추세 |

목표가 없는 기간에는 목표 달성률을 만들지 않고 전기 비교를 대체 정보로 보여 준다.

## 6. 전문 대시보드

### 6.1 RPT-010 수주

경영 질문: 얼마나 확보했고 무엇이 생산·출하 위험으로 넘어가는가?

- KPI: 수주금액·수량, 목표 달성률, 신규 거래처, 미착수, 납기 위험, 예상 매출총이익
- 그래프: 목표 대비 누적 수주, 거래처·품목 구성, 납기 예정 히트맵, 수주금액·이익 사분면, 거래처 추세
- 위험: 지시 미생성, 표준 리드타임보다 짧은 납기, 편중, 저마진·원가 미확정
- 드릴다운: 거래처 → 생산의뢰 → 품목 → 납기·진행단계

### 6.2 RPT-020 생산

경영 질문: 계획대로 생산되고 있으며 손실과 병목은 어디에 있는가?

- KPI: 계획수량, 생산수량, 달성률, 양품수량, 로스수량, 가동률, 지연 작업지시
- 그래프: 계획 대 실적, 가동·정지시간, 설비·품목별 생산성, 지시별 편차, 정지 히트맵
- 위험: 계획 미달 예상, 장시간 정지, 완료 예정일 초과, 반복 로스
- 드릴다운: 설비 → 작업지시 → 생산일보 → 품목·LOT

로스율은 D-519 확정 전까지 계산하지 않는다.

### 6.3 RPT-030 품질

경영 질문: 불량이 어디서 반복되며 출하와 고객에 어떤 영향을 주는가?

- KPI: 검사수량, 합격률, 불량수량, 불합격 LOT, 재판정, 품질보류 재고
- 그래프: 합격률·불량 추세, 불량유형 파레토, 품목·설비·지시 히트맵, 재판정 흐름, 해제 소요일
- 위험: 반복 불량, 중요 불량 급증, 장기 보류, 납기 주문과 연결된 불합격 LOT
- 드릴다운: 불량유형 → 검사결과 → LOT → 생산지시 → 원자재 LOT

### 6.4 RPT-040 재고·창고

경영 질문: 필요한 재고는 충분하고 묶인 자금과 부족 위험은 어느 정도인가?

- KPI: 현재고, 가용·할당재고, 재고금액, 장기재고, 부족 예상, 실사 차이
- 그래프: 원자재·재공·제품 구성, 재고 변화, 회전일수, 창고·품목 트리맵, 에이징, 예상 가용재고
- 위험: 안전재고 미달, 과잉·무이동, 관리기한 임박, 반복 실사 차이, 주문 대응 부족
- 드릴다운: 창고 → 품목 → LOT → 입출고 → 주문

안전재고·금액·관리기한 필드가 없으면 해당 지표는 `연계 전`으로 남긴다.

### 6.5 RPT-050 출하

경영 질문: 고객 약속을 지키며 이번 기간 매출로 전환될 물량은 안전한가?

- KPI: 출하지시, 출하완료 수량·금액, 목표 달성률, 납기 준수율, 지연, 미출하 잔량
- 그래프: 목표 대비 누적 출하, 정시·지연 추세, 거래처·품목 구성, 7·14·30일 예정 부하, 예정과 가용재고 비교
- 위험: 납기 임박 미출하, 검사·재고 차단, 거래처 반복 지연, 장기 미확정
- 드릴다운: 거래처 → 생산의뢰 → 출하지시 → 할당 LOT → 이력

### 6.6 RPT-060 수금

경영 질문: 출하가 현금으로 얼마나 전환됐고 회수 위험은 어디에 있는가?

- KPI: 출하매출, 수금액, 수금률, 미수금, 90일 초과, 평균 회수일
- 그래프: 출하매출·수금·미수, 미수 연령, 거래처 위험 사분면, 예정 대 실제 수금, 4·8·13주 유입 전망
- 위험: 약정일 초과, 장기·고액 미수, 수금 패턴 악화, ERP 기준일 미갱신
- 드릴다운: 거래처 → 월별 출하·수금 → 업로드 회차 → 원천 행

출하와 수금은 월·거래처 단위로 비교하며 개별 건을 추정하여 짝짓지 않는다.

### 6.7 RPT-070 주문흐름

경영 질문: 수주부터 현금 회수까지 어디에서 가장 오래 머무는가?

- KPI: 전체 리드타임, 단계별 체류, 지연 주문, 정상 흐름 비율, 수주→출하, 출하→수금
- 그래프: 흐름 퍼널, 단계별 체류 누적 막대, 주문 타임라인, 단계 이동량, 거래처·품목별 분포
- 위험: 기준 체류 초과, 다음 단계 미착수, 반복 정체, 납기 내 완료 가능성 저하
- 드릴다운: 위험 주문 → 단계 이력 → 담당 부서 → 업무 화면

D-520 확정 전에는 실제 소요일만 제공하고 병목 판정을 만들지 않는다.

## 7. 목표관리

### 7.1 목표 구조

목표는 지표, 기간 단위, 시작·종료일, 적용 범위, 값, 단위, 방향성을 가진다.

- 기간 단위: 연간, 월간, 주간
- 적용 범위: 전사, 부서, 거래처, 품목, 설비, 창고
- 방향성: 높을수록 좋음, 낮을수록 좋음, 범위 내 정상

연간 목표를 월간·주간으로 배분할 수 있으나 자동 배분 결과는 저장 전에 사용자가 확인한다. 수정은 기존 행을 덮어쓰지 않고 새 버전으로 만든다.

### 7.2 달성률

- 높을수록 좋음: `실적 / 목표 × 100`
- 낮을수록 좋음: 달성률 하나로 오해시키지 않고 목표 초과분과 상태를 우선 표시
- 범위형: 정상 범위 내부인지와 경계까지의 거리를 표시
- 목표가 0이거나 없으면 달성률은 `미수집`이 아니라 `목표 없음`

## 8. 위험과 조치관리

### 8.1 위험 발생

위험은 저장된 임계치 또는 확정된 업무 규칙으로만 감지한다. 위험 키는 같은 원인·대상·기간에서 중복 생성되지 않아야 하며, 재발 시 최근 관측값과 시각을 갱신한다.

위험에는 다음을 보존한다.

- 종류, 심각도, 제목
- 근거 지표와 관측값
- 관련 거래처·품목·LOT·생산의뢰 등 업무 키
- 출처 화면과 필터 링크
- 최초·최근 감지 시각
- 신규, 진행, 해결 상태

### 8.2 조치

하나의 위험에 여러 조치를 연결할 수 있다. 조치는 담당 부서, 담당자, 기한, 상태, 조치 내용, 완료자·완료시각을 가진다. 위험의 해결은 모든 필수 조치가 완료되고 원인 규칙이 더 이상 참이 아닐 때 이루어진다. 사용자가 강제 종료하는 경우 사유가 필수다.

## 9. 관리 화면과 기능 경계

삭제된 옛 RPT-090~130 ID는 재사용하지 않는다. 신규 대메뉴 `MGT 경영관리`를 만들고 다음 화면을 둔다.

| 화면 | 이름 | 경로 | 쓰기 책임 |
|---|---|---|---|
| MGT-010 | 경영목표 | `/mgt/targets` | 목표 생성·새 버전·중지 |
| MGT-020 | 경보기준 | `/mgt/thresholds` | 임계치 생성·수정·중지 |
| MGT-030 | 위험·조치 | `/mgt/issues` | 조치 배정·상태 변경·강제 종료 |
| MGT-040 | 재무자료 업로드 | `/mgt/financial-imports` | 검증·반영·회차 교체 |

RPT 대시보드에서는 이 관리 데이터를 읽기만 한다. 관리 화면은 목록 조회와 쓰기 API를 분리하며, 모든 쓰기 API는 독립 기능 ID와 `require_fn` 검사를 가진다.

기본 권한은 다음과 같다.

- MGT-010: 전략부·전산 관리자 W, 경영진·회계부 R
- MGT-020: 전략부·전산 관리자 W, 경영진 R
- MGT-030: 전 부서 W. 단, 서버가 자기 부서에 배정된 조치 또는 본인이 만든 조치만 변경하도록 제한한다. 경영진·전략부·전산 관리자는 전사 조회와 재배정이 가능하다.
- MGT-040: 회계부·전산 관리자 W, 전략부·경영진 R

## 10. 데이터 모델

DDL은 기존 `bigserial` 식별자, `timestamptz` 변경시각, 명시적 check 제약, 업무키 unique 제약 규칙을 따른다. 테이블 책임은 다음과 같다.

| 테이블 | 책임 |
|---|---|
| `management_metric` | 지표 키, 표시명, 단위, 방향성, 원천 집계 키, 활성 여부 |
| `management_target` | 현재 유효한 목표의 식별자, 범위와 상태 |
| `management_target_version` | 목표값·단위·방향·배분·변경 사유 이력 |
| `management_threshold` | 지표별 주의·위험 기준과 적용 기간·범위 |
| `management_issue` | 규칙으로 감지된 위험과 근거·업무 키 |
| `management_action` | 위험별 담당·기한·처리 이력 |
| `financial_import_batch` | 재무 업로드 회차, 기준 기간, 활성·교체·오류 상태 |
| `financial_fact` | 활성 회차의 거래처·품목·기간별 수주·출하·원가 사실 |

`management_target_version`, `management_action`, `financial_import_batch`는 이력을 삭제하지 않는다. 모든 쓰기는 `sys_change_log`에도 남긴다.

`management_target.metric_key`와 `management_threshold.metric_key`는 `management_metric`을 참조한다. 적용 범위는 `scope_kind`와 `scope_key` 한 쌍으로 표현하며 `scope_kind`는 `company`, `department`, `customer`, `item`, `equipment`, `warehouse` 중 하나다. 전사는 `scope_key`를 null로, 나머지는 실제 업무 키를 사용한다. 같은 지표·기간·범위에는 유효 목표가 하나만 존재한다.

## 11. 컴포넌트와 데이터 흐름

### 11.1 서버 컴포넌트

- `dashboard.py`: 업무 원천 집계와 8개 대시보드 읽기 모델
- 신규 `management.py`: 목표 비교, 임계치 평가, 위험·조치 읽기 모델
- 신규 `financial.py`: 재무 업로드 검증, 회차 반영, 금액·원가 집계
- RPT 라우터: 조회 조건 검증과 화면 렌더링만 담당
- 별도 관리 라우터: 목표·임계치·조치·재무 업로드 쓰기 담당
- 공통 차트 매크로: 기존 SVG와 데이터 표 계약 확장

집계 SQL을 템플릿이나 라우터에 복제하지 않는다.

### 11.2 요청 흐름

1. 라우터가 모드, 기간, 범위 필터를 검증한다.
2. `dashboard.py`가 업무 실적을 읽는다.
3. `management.py`가 같은 지표·기간·범위의 목표와 상태를 결합한다.
4. 재무 연계 지표는 `financial.py`가 활성 회차에서 읽는다.
5. 화면은 KPI, 그래프, 위험, 근거 표를 렌더링한다.
6. 드릴다운 링크는 동일 필터와 업무 키를 대상 화면으로 전달한다.

## 12. 권한과 감사

- RPT 조회: 기존 화면별 R 권한 유지
- 경영요약·재무·수금: 기존 허용 부서 계약을 기본으로 유지
- 목표 등록·수정: 경영관리 쓰기 권한
- 임계치 변경: 관리자 또는 지정 책임자 쓰기 권한
- 조치 등록·완료: 담당 부서 쓰기 권한
- 재무 업로드: 회계 담당 쓰기 권한

MGT 화면과 기능 ID는 `contracts/ia-overrides.json`, `nav.py`, `function-list.md`, `permission-matrix.md` 및 시드에 동시에 반영한다. 조회와 쓰기 기능은 별도 ID를 가진다.

## 13. 오류와 경계 상황

- 잘못된 날짜·모드·범위: 422와 사람이 읽을 수 있는 필드 오류
- 없는 업무 키: 404
- 조회 권한 없음 또는 담당 범위 밖 쓰기: 403
- DB 연결 실패: 503
- ERP 업로드 열·형식·코드 오류: 회차와 오류 행을 보존하되 반영 제외
- 목표·임계치 충돌: 겹치는 범위와 기간을 명시하여 422
- 동시 수정: 버전 불일치 시 409로 새로고침 요구
- 데이터 일부 미수집: 화면 전체를 실패시키지 않고 해당 지표 상태로 표시

## 14. 기존 결정과의 관계

- D-505: RPT-010~080 실시간 조회 원칙은 유지한다. 신규 쓰기는 별도 관리 기능이다.
- D-512·D-805: 기존 모집단·기간·0건 처리 정의를 출발점으로 확장한다.
- D-519: 생산·검사 로스율은 산식 확정 전 계산하지 않는다.
- D-520: 주문흐름 병목은 기준 확정 전 판정하지 않는다.
- D-529: 데이터 질의와 AI 호출은 재도입하지 않는다.
- D-804: 납기 준수율 모집단을 유지한다.

구현 전에 이 설계를 새 확정 결정으로 `decisions.md`에 기록하고 기존 계약의 화면 수·기능 수·권한 수 기대값을 함께 갱신한다.

## 16. 테스트와 수용 기준

### 16.1 단위·집계 테스트

- KPI별 모집단, 날짜 기준, 단위, 방향성
- 일간·주간·월간 기간과 전기 비교
- 목표 없음·0·미수집·미확정·연계 전 구분
- 높을수록 좋음·낮을수록 좋음·범위형 목표 판정
- 임계치 경계값과 위험 중복 방지·재발·해결
- 월·거래처 단위 출하 대비 수금

### 16.2 계약·보안 테스트

- 기능 목록, 라우트, 테스트 표식 1:1
- 화면·기능별 R/W/무권한 200·403 전수
- 모든 쓰기 성공의 감사로그
- RPT 조회 전후 업무·관리 테이블 행 수 불변
- ERP 오류 행 반영 제외와 이전 회차 보존

### 16.3 화면 테스트

- SVG의 각 값과 접힌 데이터 표의 값 일치
- 그래프 빈 목록, None, 실제 0, 음수 안전성
- 드릴다운 필터와 업무 키 보존
- 1280px 및 390px에서 정보 손실과 페이지 가로 스크롤 없음
- 일간·주간·월간 모드의 KPI·위험·비교 문맥 변화

### 16.4 완료 감사

기존 `make gate-full` 전건과 신규 경영 Cockpit 게이트를 실행한다. 테스트가 있다는 사실만으로 완료를 주장하지 않고, 각 요구사항을 검증하는 테스트·SQL·브라우저 결과가 실제로 존재하는지 대조한다.
