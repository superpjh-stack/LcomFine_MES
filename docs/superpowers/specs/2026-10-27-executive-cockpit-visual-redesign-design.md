# 엘컴화인 MES 경영 Cockpit 그래프 중심 리디자인

## 1. 목적과 승인 근거

경영진이 대형 모니터에서 회사 전체의 경영 흐름을 짧은 시간 안에 판단할 수 있도록 RPT-080과 RPT-010~070을 그래프 중심으로 재구성한다. 사용자는 시각 방향을 `C Executive Scoreboard > A Command Bridge > B Factory Wallboard` 순으로 선호했고, C의 재무·목표 중심 상단과 A의 7단계 흐름·위험 분석을 결합한 통합 시안을 승인했다.

이번 작업은 데이터 기능 추가보다 시각적 위계, 그래프 구성, 정보 밀도와 드릴다운 경험에 집중한다. 기존 브랜드 레드, 메뉴·화면 ID·URL·권한·감사·데이터 산식은 유지한다.

## 2. 디자인 원칙

- 대상: 대표, 임원, 전략부가 일일 점검과 주간·월간 경영회의에서 사용하는 16:9 대형 모니터.
- 디자인 리드: 제조기업용 고밀도 B2B Cockpit. 브랜드 레드를 강조색으로 쓰고 중립적인 짙은 회색 표면을 기본으로 한다.
- 다이얼: 변주 4, 모션 2, 밀도 8.
- 한 화면의 읽기 순서: 목표·재무 성과 → 위험 → 전사 흐름 → 원인 그래프.
- 숫자는 실제 데이터만 사용한다. `미수집`, `목표 없음`, `미확정`, `연계 전`, 실제 0을 구분한다.
- 색상만으로 상태를 전달하지 않는다. 상태 문구, 테두리, 아이콘 또는 패턴을 함께 사용한다.
- 장식용 애니메이션은 사용하지 않는다. 필터와 상태 변경에는 짧은 피드백만 허용하며 `prefers-reduced-motion`을 존중한다.

## 3. RPT-080 정보 구조

### 3.1 상단 제어부

- 제목을 `전사 경영 Cockpit`으로 표시한다.
- 일간·주간·월간 전환, 기준일, 거래처 필터, 조회 버튼을 한 줄에 배치한다.
- 1920px 이상에서는 한 줄을 유지하고 1280px에서는 제목과 필터를 두 줄로 분리한다.
- 필터를 변경해 각 영역으로 이동할 때 기간과 거래처 조건을 보존한다.

### 3.2 Hero KPI Scoreboard

상단 첫 행에는 최대 4개만 표시한다.

1. 목표 종합 달성률
2. 수주 매출
3. 출하 매출
4. 실제 원가 또는 예상 이익

첫 번째 KPI는 1.2배 너비로 강조한다. 각 KPI는 현재값, 목표, 달성률, 전기값, 증감, 상태를 제공한다. 재무 회차가 없으면 해당 금액만 `연계 전`으로 표시하고 운영 KPI는 유지한다. 이익은 수익과 원가가 모두 있을 때만 계산한다.

### 3.3 성과 기여와 즉시 위험

- 왼쪽 60%: 목표 종합 달성률 링과 영역별 기여 waterfall.
- 오른쪽 40%: 해결되지 않은 위험 Top 5.
- 위험 행에는 단계, 제목, 관측값, 담당 부서, 기한 또는 경과시간을 표시한다.
- 위험 행을 선택하면 MGT-030 상세 위치로 이동한다.

### 3.4 전사 7단계 흐름

`수주 → 생산대기 → 생산 → 검사 → 제품재고 → 출하 → 수금`을 연결형 프로세스 그래프로 표시한다.

각 단계는 다음 정보를 가진다.

- 대표 값: 건수, 수량, LOT 또는 금액
- 목표 달성률 또는 전환율
- 전기 증감
- 평균 체류시간
- 열린 위험 수
- 정상·주의·위험 상태

대형 모니터에서는 7단계를 한 줄에 표시한다. 1280px에서는 가로 스크롤 없이 4+3행으로 재배치하고, 768px 미만에서는 세로 흐름으로 전환한다. 단계 선택 시 해당 RPT 화면으로 동일 필터를 보존해 이동한다.

### 3.5 원인 분석 그래프

하단은 비대칭 3열로 구성한다.

- 넓은 열: 수주·출하·수금 누적 추세. 단위가 다른 경우 차트를 분리하며 이중 Y축을 쓰지 않는다.
- 중간 열: 향후 7일 납기 위험 전망.
- 오른쪽 열: 불량 원인 Pareto.

모든 그래프는 SVG의 값과 접근 가능한 데이터 표가 동일해야 한다. 범례와 툴팁은 실제 단위와 기간을 포함한다.

## 4. RPT-010~070 시각 체계

각 업무 대시보드는 같은 위계를 사용한다.

1. 대표 KPI 3~5개
2. 목표 대비 누적 추세 또는 계획·실적 그래프
3. 위험·구성·Pareto 그래프
4. 상세 드릴다운 표

영역별 대표 그래프는 다음과 같다.

- RPT-010 수주: 목표 대비 누적 수주, 거래처·품목 구성, 납기 위험과 미착수.
- RPT-020 생산: 계획 대비 생산실적, 설비별 가동·정지, 지연 지시. D-519 로스율은 미확정으로 유지한다.
- RPT-030 품질: 합격·불합격 추세, 불량 Pareto, 반복 불량, 보류 LOT.
- RPT-040 재고·창고: 현재·가용·할당 구성, 체류 에이징, 실사 차이. 안전재고와 금액은 확정 데이터가 없으면 `연계 전`이다.
- RPT-050 출하: 목표 대비 누적 출하, 7·14·30일 부하, 납기 위험과 차단 원인.
- RPT-060 수금: 출하·매출·수금 추세, 미수 연령, 거래처 위험과 ERP 기준일.
- RPT-070 주문흐름: 단계별 체류시간, 의뢰 타임라인, 미착수 다음 단계. D-520 병목 기준은 미확정으로 유지한다.

## 5. 공통 컴포넌트

- `cockpit_hero_kpis`: 최대 4개의 경영 KPI.
- `attainment_ring`: 목표 종합 달성률. 목표가 없으면 링 대신 `목표 없음` 상태를 표시한다.
- `contribution_waterfall`: 영역별 목표 달성 기여.
- `executive_risk_list`: 열린 위험 Top 5.
- `process_flow`: 7단계 연결형 흐름.
- `comparison_chart`: 현재, 목표, 전기의 단일 단위 비교.
- `forecast_bars`: 향후 7·14·30일 부하와 위험.
- `pareto_chart`: 원인별 막대와 누적 비율.
- `chart_table`: 그래프와 같은 데이터를 제공하는 접근성 표.

Jinja 매크로는 데이터 변환을 하지 않고 표시만 담당한다. 집계·비교·상태 계산은 `dashboard.py` 읽기 모델에 둔다.

## 6. 데이터와 상태 처리

공통 KPI 모양은 `value`, `target`, `attainment`, `previous`, `delta`, `status`, `availability`, `unit`, `digits`를 유지한다. 흐름 단계는 `key`, `label`, `value`, `secondary`, `conversion`, `dwell`, `risk_count`, `status`, `href`를 제공한다.

- 데이터 없음: 빈 그래프 대신 의미 있는 빈 상태와 다음 행동을 표시한다.
- 실제 0: 숫자 0을 표시하며 `미수집`으로 바꾸지 않는다.
- 목표 없음: 현재 실적은 표시하고 비교 영역에 `목표 없음`을 표시한다.
- 미확정: D-519·D-520 결정 번호와 원 수량을 함께 표시한다.
- 재무 미연계: 금액 관련 요소만 `연계 전`으로 표시한다.
- 오류: 기존 422·503 규약을 유지하고 필터 영역 가까이에 오류를 표시한다.

## 7. 반응형과 화면 규격

- 기준 설계: 3840×2160과 2560×1440 대형 모니터.
- 필수 지원: 1920×1080, 1280px, 390px.
- 1920px 이상에서는 첫 화면에 Hero KPI, 성과·위험, 7단계 흐름이 함께 보여야 한다.
- 대형 모니터에서 본문 최대폭을 기존보다 넓히되, 표의 한 행이 지나치게 길어지지 않도록 그래프 폭과 표 폭을 분리한다.
- 숫자는 고정폭 숫자 렌더링을 적용한다.
- 모바일은 그래프 요약을 우선하고 상세 표는 접힌 상태로 제공한다.

## 8. 시각 토큰

- 브랜드 강조: 기존 crimson 계열 `--brand`를 유지한다.
- 배경과 표면: 중립적인 charcoal 계열. 순수 검정과 순수 흰색은 사용하지 않는다.
- 정상: 녹색, 주의: amber, 위험: 브랜드 레드와 구분되는 상태 red.
- 카드 모서리는 기존 시스템의 작은 반경 하나로 통일한다.
- KPI를 모두 박스에 넣지 않는다. Hero와 실제 계층이 필요한 패널에만 표면을 사용한다.
- 라이트·다크 모드는 기존 토큰 체계를 유지하며 같은 정보 위계를 제공한다.

## 9. 접근성과 상호작용

- 그래프마다 제목, 단위, 기간을 제공한다.
- SVG 값과 데이터 표의 행 순서·숫자가 일치해야 한다.
- 키보드로 모든 필터, 단계 링크, 위험 링크와 데이터 표를 사용할 수 있어야 한다.
- 상태는 색 외에 글자와 테두리로 구분한다.
- 포커스 링과 텍스트 대비는 WCAG AA를 충족한다.
- 자동 재생과 무한 애니메이션은 사용하지 않는다.

## 10. 구현 경계

- 수정 대상: `dashboard.py`, `routers/rpt.py`, `_charts.html`, `rpt/_d.html`, `rpt/summary.html`, RPT-010~070 템플릿, `style.css`, 관련 테스트.
- 변경하지 않는 것: 라우트, 화면 ID, 메뉴 이름, 권한, 쓰기 경계, 데이터 산식 정본, MGT 쓰기 화면의 기능 계약.
- RPT GET은 계속 읽기 전용이며 캐시 테이블을 만들지 않는다.
- 새 외부 차트 라이브러리는 추가하지 않고 기존 인라인 SVG와 Jinja 매크로를 확장한다.

## 11. 검증 기준

- 기존 436개 테스트와 G-01~G-24를 유지한다.
- 새 계약 테스트: Hero KPI 필드, 7단계 모양, 목표·전기·상태, 재무 `연계 전`, 위험 Top 5.
- 그래프 테스트: SVG title과 데이터 표의 라벨·값·순서 일치.
- 읽기 경계: RPT 8개 GET 전후 업무·관리 테이블 행 수 불변.
- 권한: 기존 8부서 200/403 계약 유지.
- 시각 QA: 3840×2160, 1920×1080, 1280px, 390px에서 가로 넘침과 겹침이 없어야 한다.
- 라이트·다크, 정상·주의·위험, 미수집·0·목표 없음·미확정·연계 전 상태를 모두 확인한다.

## 12. 완료 정의

경영진이 대형 모니터의 첫 화면에서 목표·재무 성과, 즉시 위험, 7단계 흐름을 동시에 읽고, 한 번의 선택으로 원인 대시보드까지 이동할 수 있어야 한다. 기존 테스트와 `gate-full`은 FAIL·미검증·BLOCKED 0을 유지해야 한다.
