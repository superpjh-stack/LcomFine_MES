# 엘컴화인 AI 운영 플랫폼 기획·디자인·개발 로드맵

## 1. 추진 목적

엘컴화인에 이미 축적된 생산·영업·회계 데이터를 연결해, 경영진은 회사 전체의 병목과 의사결정 사항을 보고 현장은 빠르고 오류 없이 데이터를 입력하는 운영 플랫폼을 만든다.

최종 목표는 인쇄업계에서 재현 가능한 AI 성공사례를 만드는 것이다.

```text
기존 데이터 축적
  → 데이터 표준화·연결
  → MES 진행 가시화
  → 현장 바코드·설비 수집
  → AI 분석·예측·추천
  → 납기·품질·생산성 개선
```

## 2. 사용자와 성공 기준

### 경영진

- 오늘 지연·위험한 수주를 30초 안에 찾는다.
- 병목 공정·공장·설비를 확인한다.
- AI 결론의 근거 데이터와 추천 조치를 함께 본다.
- 수주·생산·출하·매출·수금의 연결 상태를 확인한다.

### 생산·출하 담당자

- 수주별 현재 공정과 다음 작업을 바로 확인한다.
- 지연 원인을 찾고 담당 화면으로 이동한다.
- 현장 입력을 최소 단계로 처리한다.

### 작업자

- 입고·불출·출하를 바코드로 처리한다.
- 생산·검사 데이터를 중복 입력하지 않는다.
- 모바일·태블릿·공장 모니터에서 읽기 쉽다.

성공 기준은 화면 수가 아니라 다음 운영 결과로 판단한다.

- 수주부터 출하까지 추적 가능한 비율
- 미입력·코드 불일치 데이터 감소율
- 납기 지연 사전 발견 건수
- 현장 바코드 처리 비율
- AI 추천 조치의 실행·완료율
- 경영진 대시보드 주간 사용률

## 3. 1차 범위 — 경영 대시보드

현재 대시보드의 `RPT-080 경영 요약`을 운영 관제 화면으로 확장한다. 상단 메뉴에서 대시보드가 먼저 보이며, 경영 요약이 첫 탭이다.

### 화면 순서

```text
[오늘의 경영 상태]
[우선 확인 수주 10건]
[전사 공정 흐름]
[위험·납기·품질]
[수주·생산·출하·매출·수금 연결]
[상세 리포트]
```

### 핵심 컴포넌트

1. 오늘의 경영 상태
   - 전체 수주
   - 지연 수주
   - 납기 3일 이내
   - 생산 병목
   - 출하 대기
   - 데이터 신뢰도·기준일

2. 우선 확인 수주 10건
   - 지연 → 납기 임박 → 공정 정체 → 최근 변경 순
   - 수주번호·거래처·품목·현재 단계·D-day·잔량
   - 단계별 빨간 현재 위치 표시
   - 클릭 시 TRK-010 상세
   - 전체 수주는 상세 화면에서 확인

3. 전사 공정 흐름
   - 수주 → 자재 발주/입고 → 생산 → 검사 → 제품 입고 → 출하
   - 단계별 건수·정상/주의/위험
   - 클릭 시 관련 리포트

4. 위험·원인·조치
   - 위험 제목
   - 관측값과 기준값
   - 근거 화면·데이터 기준일
   - 담당 부서·담당자·기한
   - 조치 상태

5. AI 인사이트 영역

   초기에는 규칙 기반 설명으로 시작하고, 데이터 품질이 확보된 뒤 ML/LLM 분석을 붙인다.

   ```text
   결론: 검사 공정에서 4건이 지연되고 있습니다.
   근거: 최근 7일 검사 대기 평균 2.4일, 기준 1일.
   원인 후보: 검사일보 미입력 2건, 재검사 2건.
   추천 조치: 검사 담당자 배정 및 오늘 15시 재확인.
   ```

## 4. 데이터 표준화 설계

### 기준 코드

- 고객·거래처 코드
- 품목·제품·원자재 코드
- 설비·공장 코드
- 공정·상태 코드
- LOT·수주·작업지시 연결키
- 회계 계정·매출·수금 코드

### 데이터 품질 규칙

- 코드 없는 행
- 동일 대상 중복 코드
- 날짜 역전
- 수주량·생산량·출하량 불일치
- 출하 후 검사 상태 변경
- 회계 거래처와 MES 거래처 미매핑
- 설비 데이터 수집 중단

대시보드의 모든 숫자는 `수집 기준일`, `원천 화면`, `데이터 상태(수집·미수집·미확정)`를 함께 제공한다.

## 5. 현장·설비 확장

### 바코드 1차

- 원자재 입고: LOT 생성·입고검사 대기
- 불출: 원자재 LOT와 작업지시 연결
- 제품 입고: 제품 LOT와 작업지시 연결
- 출하: 제품 LOT 확인·출하 확정

### 설비 수집 파일럿

공장 한 곳의 인쇄기 1~2대를 먼저 연결한다.

- 생산 수량
- 작업 시작·종료
- 설비 정지
- 정지 사유
- 속도·가동 시간
- 오류 코드

업체 응답이 지연될 경우 파일 수집·수기 업로드·임시 게이트웨이를 대안으로 검토한다. 8대 전체 확장은 파일럿 데이터 품질 확인 뒤 진행한다.

## 6. AI 적용 순서

1. 규칙 기반 경보
   - 납기 D-3
   - 공정 체류시간 초과
   - 품질 불합격·재검사
   - 데이터 누락·불일치

2. 분석형 AI
   - 병목 원인 요약
   - 거래처·제품·설비별 추세
   - 과거 유사 수주 비교

3. 예측형 AI
   - 납기 지연 가능성
   - 불량 가능성
   - 설비 정지 가능성
   - 예상 생산 완료일

4. 대화형 AI
   - “이번 주 지연 위험 수주는?”
   - “검사 대기 원인은?”
   - “출하 전 확인해야 할 LOT는?”

AI 답변에는 항상 근거 레코드와 원천 화면 링크를 포함한다. 자동 설비 제어는 범위에서 제외하고 의사결정 지원만 한다.

## 7. 단계별 개발 계획

### Phase 1 — 경영 대시보드 기반

- RPT-080 첫 화면 개편
- 수주 우선순위 10건
- 전사 공정 흐름
- 위험·조치 카드
- 데이터 기준일·신뢰도
- 대표실·사무실 모니터용 반응형 레이아웃

### Phase 2 — 데이터 품질·표준화

- 코드 매핑 화면
- 데이터 품질 점검 결과
- 누락·중복·불일치 리포트
- 영업·회계 데이터 연결 강화

### Phase 3 — 현장 입력

- 바코드 입고·불출·제품입고·출하
- 모바일·태블릿 화면
- 작업자별 최소 입력 플로우

### Phase 4 — 설비 수집

- 1~2대 파일럿
- 수집 서버·장애 모니터링
- 8대 확장

### Phase 5 — AI 분석·예측

- 규칙 기반 인사이트
- 근거 추적형 AI 요약
- 지연·품질·설비 예측
- 경영진·현장용 질의 인터페이스

## 8. 1차 구현 검증 기준

- 대시보드가 상단 메뉴의 첫 화면으로 열린다.
- 첫 화면에 우선순위 수주 10건만 보인다.
- 나머지 수주는 TRK-010에서 조회할 수 있다.
- 각 숫자에 기준일과 원천 화면이 있다.
- 수주·생산·검사·출하·수금 숫자가 기존 리포트와 일치한다.
- 지연·주의·정상 상태가 명확히 구분된다.
- 데이터가 없을 때 0으로 꾸미지 않고 미수집/미확정으로 표시한다.
- 대표실·사무실 모니터에서 1분 안에 핵심 상황을 이해할 수 있다.
- 기존 권한·URL·업무 입력 흐름이 깨지지 않는다.

## 9. 범위 원칙

- 기존 데이터를 먼저 연결하고 신규 입력은 최소화한다.
- AI보다 데이터 품질과 추적성을 먼저 확보한다.
- 경영진 화면과 현장 화면을 같은 데이터로 연결하되 표현은 다르게 한다.
- 자동 제어가 아닌 근거 있는 의사결정 지원으로 시작한다.
- 매 단계에서 경영진·생산상무·현장 사용자의 피드백을 반영한다.
