예외는 계약 문장의 표지로만 허용한다(`contracts._validate` · `tests/test_arch_contracts.py` 가 이 낱말을 본다):
- **「수정 없음」** — 정본 logic 이 수정을 막는 등록 화면: INV-030(조정 이력 불변) · COL-010(MES 는 수금 데이터를 고치지 않는다).
- **「유형 예외」** — 정본 type 밖 쓰기 기능 하나를 그 화면 끝에 더한다. 셋뿐이다: RPT-130 질의 실행(`data_query_log` · `sys_ai_call_log` · D-513) · SHP-020 반품·정정 등록(정본 「확정 후 정정은 반품·정정 행」 · `shipment_adjust` · D-515) · HOME-020 알림 처리(정본 「처리하면 닫힘」 · `notification` · D-511).
- **「권한 예외」** — 정본 칸에 W 가 없는 화면의 쓰기 기능: F-DOC-011 문서관리 진입 · F-RPT-132 질의 실행 · F-HOME-022 알림 처리. 권한 칸 `R 이상(권한 예외)` · `Function.permission_exception` 이 참이고, `rbac.require_fn` 은 이 셋에 화면 R 이상을 본다(D-511 · D-513 · D-514).
- 삭제는 경로를 `/{id}/delete` 로 통일하되, 참조가 생기는 기준 데이터는 「참조가 있으면 지우지 않고 사용 중지로 바꾼다」(SYS-010 은 비활성).

공통 규칙 — 쓰기는 `rbac.require_fn("<ID>")`, 쓰기 뒤에는 `audit.log_change(...)`, 번호는 `numbering.next(kind)` 한 곳(형식 D-509),
알림은 `notify.emit(...)` 한 곳(쓰기 트랜잭션 안 · D-511), 추적은 `trace`, 집계 SQL 은 `stats` · `dashboard` 뿐. 쓰기 기능은 공통으로 「누락 422 · 없는 ID 404」.
